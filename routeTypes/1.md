# Route type `1` — Bitcoin address

## Status

Accepted

## Summary

`target` is a Bitcoin payment address encoded as a UTF-8 string (e.g. Legacy,
P2SH, or Bech32/Bech32m).

## Encoding

Set `routeType` to `1`. `target` MUST be the UTF-8 bytes of a Bitcoin address string
(non-empty; no `0x` prefix; no null terminators) — e.g. Legacy, P2SH, or Bech32/Bech32m.

Examples (as UTF-8 in `target`):

```text
bc1qxy2kgdygjrsqtzq2n0yrf2493p83kkfjhx0wlh
1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa
3J98t1WpEZ73CNmYviecrnyiWrnqRhWNLy
```

## Decoding

1. Require `target.length > 0`.
2. Decode `target` as UTF-8 into a string.
3. Validate with a Bitcoin address library appropriate for the networks the
   application supports (mainnet / testnet / etc.).
4. Reject if the string is not a valid address for the intended network.

## Non-goals

- Does not embed network / chain metadata in `target` (apps choose network context).
- Does not use raw scriptPubKey or PSBT encoding (define a separate type if needed).
- Does not standardize a preferred address format (P2WPKH vs P2TR, etc.).

## Compatibility notes

Applications SHOULD document which Bitcoin networks and address formats they accept.
Invalid checksums or unsupported formats MUST be rejected.
